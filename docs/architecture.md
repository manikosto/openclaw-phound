## At a glance

- **Platform:** none · native
- **What it is:** an OpenClaw **channel plugin** (`openclaw-phound` v0.1.3, `package.json:3`). It connects an OpenClaw agent to **Phound**, so people can reach the agent through Phound app chats, SMS, voice messages and phone calls. The agent can also place calls, using the `phound_call` tool.
- **Shape:** two processes per configured account.
  1. **TypeScript plugin** (loaded inside the OpenClaw gateway). It owns every decision: auth/pairing, routing, replies and call policy.
  2. **Python bridge** (`bridge/phound_bridge.py`), spawned as a child process. It runs the Phound SDK and its closed-source `uccrobot` binary, and talks to the plugin over **newline-delimited JSON on stdin/stdout**.

  Call audio skips the bridge. The plugin connects straight to a Phound PCM **WebSocket** stream and pipes it into OpenClaw's **realtime voice engine**.
- **Core abstractions (god nodes):** `PhoundCallSession` (live call transport), `PhoundBridge` (Node side of the JSON-lines link), and on the Python side `CallHandler` / `ChatHandler` / `Commands`. `normalizePhoneNumber()` is the identity primitive that everything keys on.
- **Mode:** single repo. There are no `apps/`/`services/`/`packages/` folders and no nested `.git`.
- **No datastore of its own.** All state is in-memory maps (see Notes). Persistent state (pairing allowlist, sessions, media) lives in OpenClaw and is reached through `PluginRuntime["channel"]`.

## Conventions

- **ESM with `.js` import suffixes** in TS sources (`import … from "./bridge.js"`), as `NodeNext` resolution requires.
- **Strict TS** with `noUncheckedIndexedAccess`, so you will see `!` on array indexes (`src/targets.ts:45`, `src/tools.ts:37`). `tsconfig.json` only `include`s `index.ts` and `src/**`. **Tests and `scripts/` are not typechecked by `npm run typecheck`.** For example, the test account fixtures omit `contacts` (`test/bridge.test.ts:11`).
- **OpenClaw SDK imports are by subpath** (`openclaw/plugin-sdk/channel-core`, `…/channel-inbound`, `…/realtime-voice`, …). SDK subpaths that ship without `.d.ts` get hand-declared in `src/voice/openclaw-voice.d.ts`. When you use a new export from those modules, declare it there.
- **Forward-compat via namespace reads.** `engine.ts:118-121` prefers `resolveConfiguredRealtimeVoiceProviderAsync` and falls back to the sync resolver, which is due for removal in Jan 2027.
- **The config schema has one source.** `src/config-schema.ts` (zod) produces the JSON schema in `openclaw.plugin.json#channelConfigs`; run `npm run gen:manifest` after any schema change. Setup fields are duplicated by hand in three places: `package.json` `openclaw.channel.setup.fields`, `src/channel.ts:68-92` (`defineChannelSetupContract`) and `SETUP_KEYS` (`channel.ts:66`). Keep them in sync.
- **Agent tools must be listed in the manifest.** Every tool registered in `src/tools.ts` must also appear in `openclaw.plugin.json` → `contracts.tools`.
- **Identity rules** (`src/targets.ts:1-9`): a phone number is only ever written with a leading `+`. Bare digits are a **persona uid**. Sender ids are the phone number if there is one, otherwise the persona uid (`phoundSenderId`, `targets.ts:89`).
- **Security conventions are embedded in code comments.** Phone caller ID is treated as spoofable: phone calls get their own session `call:+…` (`gateway.ts:42-50`) and `phoneToolPolicy` (default `none`), and the voice consult always runs with `senderIsOwner: false` (`engine.ts:169`). The bridge inherits an env **allow-list** only, not the gateway's environment (`bridge.ts:53-71`). Contact numbers never go into tool results (`tools.ts:76-77`).
- **Bridge protocol shape.** Events are `{"event": <name>, ...fields}`. Commands are `{"id", "cmd", ...fields}` and get the reply `{"event":"reply","id","ok","result"|"error"}`. Python command handlers are methods named `cmd_<name>` on `Commands`, found by dynamic `getattr` (`phound_bridge.py:170-175`). Bridge stdout is reserved for the wire; everything else goes to stderr (`phound_bridge.py:243-244`).
- **Comments explain the "why"** (platform quirks, security reasons). Keep that style.
- **No lint/format tooling is configured.** There is no eslint, prettier, ruff or black config in the repo. The visible style is two-space indent, double quotes and trailing commas.
- **Tests** are `test/<area>.test.ts` and use `node:test`. They exercise real code against fakes: the real Python bridge against `test/fake_phound`, and a real `ws` server standing in for the Phound stream with an injected `startEngine`. Tests do **not** hit Phound or OpenAI.

## Build / run / test

Requirements:
- Node + npm. Install OpenClaw ≥ 2026.10.7 as a dev dependency.
- Python ≥ 3.11 with **uv** on `PATH`. By default the bridge runs as `uv run --quiet --project bridge python bridge/phound_bridge.py` (`bridge.ts:73-79`). Set `channels.phound.pythonCommand` to override that.
- `bridge.test.ts` needs `python3` on `PATH`. It runs the real bridge with `PYTHONPATH=test/fake_phound`, so it needs neither the real SDK nor network access.

| Task | Command |
|---|---|
| Install JS deps | `npm install` |
| Install bridge deps (optional; the plugin's `uv run` does it on first start) | `uv sync --project bridge` |
| Typecheck | `npm run typecheck` (`tsc -p .`, no emit, `src/` + `index.ts` only) |
| Test | `npm test` (`tsx --test test/*.test.ts`) |
| Build | `npm run build` (`tsc -p tsconfig.build.json` → `dist/`; also runs on `prepack`) |
| Regenerate manifest schema | `npm run gen:manifest` |
| Install into an OpenClaw (users) | `openclaw plugins install clawhub:openclaw-phound --accept-capabilities` then `openclaw channels add phound --token <TOKEN> --persona-uid <PERSONAS>` |
| Docker | `printf 'OPENAI_API_KEY=...\nPHOUND_TOKEN=...\n' > .env && docker compose up -d --build` |

Environment variables:
- `PHOUND_TOKEN` and `PHOUND_SBC` are fallbacks for the **default account only** (`accounts.ts:77-92`).
- These are forwarded to the bridge: `PHOUND_LOG_DIR`, `PHOUND_REPLY_TIMEOUT`, `PHOUND_BRIDGE_LOG_LEVEL` (default `INFO`), `UCCROBOT_QUIET`, `UCCROBOT_DEBUG` (`bridge.ts:60`).
- `PHOUND_DEBUG_AUDIO_DIR` dumps raw PCM for both directions of every call (`call-session.ts:62`).
- The bridge receives `TOKEN`, `SBC` and `PERSONAS`, built from config (`bridge.ts:117-121`).
- Calls also need OpenClaw `talk.realtime.provider` plus that provider's API key. Voice messages need `tools.media.audio`.

Logs: bridge stderr lines are forwarded to the gateway log. Lines containing `ERROR`/`CRITICAL` are logged as warn, the rest as debug (`bridge.ts:146-156`). Calls log a stats line when they close and a latency timeline (`engine.ts:176-181`).

## Structure

### Core abstractions (god nodes)

| Node | Location | What it is / what connects |
|---|---|---|
| `PhoundCallSession` (18 edges) | `src/voice/call-session.ts:38` | One live call. It opens the `ws` stream (`attachStream`, :75), resamples 16 kHz⇄24 kHz, paces 20 ms frames (`pump`, :237), handles barge-in (`clearPlayback`, :225), and starts the engine (:150). It is created by `gateway.ts` (inbound :156, outbound :94), stored in the module-level `calls` registry (:303) and looked up by `tools.ts` (`phound_hangup`). |
| `CallHandler` (16) | `bridge/phound_bridge.py:98` | Phound SDK call handler in the bridge. It emits `call_incoming/outgoing/chat/ready/stream/dtmf/failed/hangup`. While ringing, it blocks for up to 15 s waiting for the plugin's `call_decision` (:110-132). |
| `PhoundBridge` (14) | `src/bridge.ts:81` | Spawns the Python bridge and gives each request an `id` with a 20 s timeout. It re-emits bridge events as Node events and holds the learnt maps `chatByNumber`, `personaByChat` and `lastPersonaUid`. Used by `gateway.ts`, `send.ts`, `inbound.ts` and `call-session.ts`. |
| `Phound` (14) | SDK; faked at `test/fake_phound/phound/__init__.py:18` | SDK entry used by `main()` (`phound_bridge.py:253`). The graph links it to the fake because the real SDK isn't in the repo. |
| `Commands` (13) | `bridge/phound_bridge.py:164` | stdin command dispatcher: `send`, `typing`, `call_decision`, `hangup`, `call`. |
| `normalizePhoneNumber()` (13) | `src/targets.ts:18` | Canonical `+digits` form. Used for sender ids, allowFrom, contacts, `callAllow` and the `chatByNumber` keys. |
| `BaseCallHandler` / `BaseChatHandler` / `StreamStatus` | SDK (faked in `test/fake_phound/phound/handlers.py`, `events.py`) | SDK base classes and enums the bridge builds on. |
| `ChatHandler` (10) | `bridge/phound_bridge.py:77` | Registers each chat for direct sends and emits `message` / `voice_message`. |

Also central, though not in the graph's top 10: `phoundPlugin` (`src/channel.ts:124`), which is the whole OpenClaw-facing surface, and `runPhoundAccount` (`src/gateway.ts:275`).

### Key flows

**1. Plugin load and account start**
```
index.ts:6 defineChannelPluginEntry
  → setPhoundRuntime (runtime.ts) · registerPhoundTools (tools.ts:40)
  → OpenClaw calls phoundPlugin.gateway.startAccount (channel.ts:198)
  → runPhoundAccount (gateway.ts:275): new PhoundBridge, wireBridgeEvents, contexts/bridges registries
  → PhoundBridge.start (bridge.ts:107): spawn `uv run … phound_bridge.py`, env allow-list
  → bridge main() (phound_bridge.py:241): Phound() + handlers + stdin reader → emits "ready"
  → onConnected → status sink; on exit: restart with backoff 2 s…60 s (gateway.ts:301-320)
```

**2. Inbound chat / SMS / voice message → agent reply**
```
SDK → ChatHandler.on_message / on_voice_message_completed (phound_bridge.py:87,90)
  → stdout {"event":"message"|"voice_message"} → PhoundBridge.onLine (bridge.ts:193) emit
  → gateway.ts:83 → handlePhoundChatMessage (inbound.ts:262)
      learn chatByNumber / personaByChat; voice: isPhoundSenderAllowed → saveRemoteMedia
  → dispatchPhoundTurn (inbound.ts:83): authorizeSender (ingress.resolveStable, dmPolicy/pairing)
      ├─ not allowed + pairing → pairing challenge reply
      └─ allowed → routing.resolveAgentRoute → inbound.run(buildContext …)
  → agent reply → deliver → sendPhoundText (send.ts:39) → bridge.request("send")
  → Commands.cmd_send (phound_bridge.py:177) → handler.send_message_nowait / phound.send_message_nowait
```

**3. Incoming phone call**
```
CallHandler.on_incoming_call (phound_bridge.py:110) emits call_incoming, waits ≤15 s
  → handleIncomingCall (gateway.ts:137): voice.enabled && isPhoundSenderAllowed
  → registerCall(new PhoundCallSession) → bridge.request("call_decision", {accept})
  → cmd_call_decision sets event → answer() → on_call_ready → start_stream("pcm", 16000, 320)
  → on_stream_update emits call_stream {url} → gateway.ts:123 → PhoundCallSession.attachStream
  → ws open → startVoiceEngine (engine.ts:123): realtime provider + consultRealtimeVoiceAgent
  → audio: ws "audio" frames → resample → engine.sendAudio; engine audio → frames → pump → ws
  → end_call tool / call_hangup event → hangup()/removeCall().close()
```

**4. Agent places a call (`phound_call`)**
```
tools.ts:41 phound_call.execute → placePhoundCall (gateway.ts:215)
  → resolveCallTarget (contacts by name or E.164) → isPhoundSenderAllowed → assertCallAllowed (:177)
  → pendingOutbound.set(number, {opening, purpose, conversational})
  → bridge.request("call") → cmd_call → phound.make_call
  → on_outgoing_call emits call_outgoing → gateway.ts:90 pops pendingOutbound → PhoundCallSession
  → then as flow 3 from call_stream; notifyOnly calls hang up after the first response (engine.ts:263)
```

**5. Proactive outbound text (`message` tool / pairing approval)**
```
OpenClaw outbound.resolveTarget / sendText (channel.ts:263, :118)
  → sendPhoundText (send.ts:39): parsePhoundTarget → chat id (phone needs a known chatByNumber entry)
  → markdown unless chat is a known SMS chat (toPlainText) → bridge.request("send")
```

### Notes

- **No import cycles** (graph: "None detected").
- **In-memory, process-local state**, invisible to any schema and lost on gateway restart:
  - `bridges` map (`bridge.ts:227`)
  - `contexts` map, which holds `pendingOutbound` (`gateway.ts:35`)
  - `calls` map (`call-session.ts:303`)
  - `PhoundBridge.chatByNumber` / `personaByChat` / `lastPersonaUid` (`bridge.ts:90-94`)
  - Python `Registry` (`phound_bridge.py:48`)

  Consequence: texting a phone number only works after an SMS or call with that number since the gateway started (`send.ts:60-65`).
- **`PhoundBridge` is a single point.** Every Phound action from every module (send, typing, call, hangup, call_decision) goes through `PhoundBridge.request` → `Commands.handle`. The bridge is the only process that runs the SDK.
- **Matching outbound calls is heuristic.** `pendingOutbound` is keyed by the normalized dialled number and is resolved when `call_outgoing` arrives (`gateway.ts:90-93`). Two concurrent calls to the same number would overwrite each other's entry.
- **`findCall` fallback** (`call-session.ts:320-332`): with no `callId` and no matching `sessionKey`, it returns the only active call if exactly one exists.
- **SMS detection is inferred.** A chat counts as SMS only if it appears in `chatByNumber` (`send.ts:8-15`).
- **Dynamic dispatch limits static analysis.** Bridge commands resolve by `getattr(self, f"cmd_{name}")` (`phound_bridge.py:172`), and Node handlers attach by event-name string (`bridge.on("call_stream", …)`). The graph cannot fully link plugin request names to Python handlers; the table under "Bridge protocol shape" in Conventions plus `gateway.ts:65-135` are the authoritative map. The bridge also emits `call_ready` and `call_dtmf`, and **nothing on the Node side subscribes to them** today.
- **The graph's "surprising connections"** (`Wire` → `MessageTextFormat`, `StreamStatus`, …) are INFERRED edges. They come from the bridge's module-level SDK imports resolving to `test/fake_phound`, because the real SDK is not in the repo. They are not real coupling between `Wire` and those types.
- **The graph may lag the code.** It was built from commit `d6c65462`; HEAD is `edba0d0`.
- **The manifest is partly generated.** `openclaw.plugin.json#channelConfigs` comes from `gen:manifest`; `contracts.tools` and the rest are maintained by hand.
